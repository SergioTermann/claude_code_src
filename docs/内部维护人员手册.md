## 2. Ubuntu 部署

上传压缩包到 Ubuntu 服务器后执行：

```bash
tar -xzf claude-code-src-full-ubuntu-portable-20260629_180146.tar.gz
cd claude-code-src-full-ubuntu-portable-20260629_180146
./run_web_portable.sh
```

默认访问地址：

```text
http://服务器IP:5002
```

默认模型接口配置为本机 vLLM：

```text
LMSTUDIO_BASE_URL=http://10.46.161.210:9527
VLLM_API_URL=http://10.46.161.210:9527/v1/chat/completions
LMSTUDIO_MODEL=Qwen-30B
```

如果实际 vLLM 模型名不同，可用环境变量覆盖：

```bash
LMSTUDIO_MODEL=实际模型名称 VLLM_MODEL_NAME=实际模型名称 ./run_web_portable.sh
```

### 2.1 进入 Docker 工程目录

现场维护时，先进入服务器终端，然后按 `d` 进入 Docker 环境。进入后默认位置通常是：

```text
/workspace
```

工程目录在：

```text
/workspace/windrise/
```

进入方式：

```bash
cd /workspace/windrise
ls
cd claude*
pwd
```

`claude*` 目录就是当前智能助手工程目录。后文所有添加 md、替换 Excel、导入用户、重建索引、打包发布等命令，默认都在这个工程目录下执行。

如果 `/workspace/windrise` 下有多个 `claude` 开头目录，先用下面命令查看时间，进入最新使用的那个目录：

```bash
ls -lt /workspace/windrise
```

## 3. 用户管理

用户管理统一在网页界面操作。用管理员账号 `admin` 登录后，点击页面右上角“用户管理”。

普通用户默认规则：

- 用户名：工号
- 初始密码：工号

管理员可在界面里完成：

- 新增用户
- 修改用户姓名
- 重置用户密码
- 启用或停用用户
- 设置或取消管理员权限

`names.csv` 和导入脚本只用于批量初始化或异常恢复，日常不要直接操作数据库文件。

## 4. 新增或修改 md 资料

资料目录：

```text
风机故障码/故障信息整理/
```

建议路径格式：

```text
风机故障码/故障信息整理/厂家/机型/资料文件.md
```

### 4.1 新增 md 放置方式

新资料建议按“厂家/机型”分目录存放，便于后续排查来源。例如：

```text
风机故障码/故障信息整理/华锐/SL1500-ABB系列/华锐SL1500-ABB系列新增故障.md
风机故障码/故障信息整理/中车山东/CWT系列/中车山东CWT系列新增故障.md
```

如果只有一个厂家资料文件，也可以把多个故障写在同一个 md 里；如果资料来自不同厂家或不同机型，建议拆开存放。

### 4.2 md 内容格式

推荐每条故障尽量保留这些字段：

- 品牌/厂家
- 机型/系列
- 具体型号，如果有
- 故障代码
- 故障名称或故障解释
- 故障类型
- 故障原因
- 故障现象及处理方法
- 来源说明，如果有

推荐写法：

```text
品牌：华锐。机型：SL1500-ABB系列。故障代码：8。故障解释：SS-7轮毂超速。故障类型：安全链。故障原因：叶轮转速突变或超过限制值。故障现象及处理方法：1.检查...
```

也可以分行写，系统会识别常见字段：

```text
品牌：华锐
机型：SL1500-ABB系列
故障代码：8
故障解释：SS-7轮毂超速
故障类型：安全链
故障原因：叶轮转速突变或超过限制值
故障现象及处理方法：
1. 检查NCC310-K228.6继电器触点至PLC240.3 E62.6继电器是否正常。
2. 检查相关线路是否松动。
```

注意事项：

- 同一个 md 可以包含多条故障，但每条故障必须有清楚的“故障代码”或“故障名称/故障解释”。
- 不建议只放扫描图片；如果资料是图片或 PDF，先整理成可复制文字再放入 md。
- 机型名称尽量和 `场站-型号映射表.xlsx` 中的机型保持一致，例如 `SL1500-ABB系列`、`CWT系列`。
- 不要直接修改 `风机故障码/fault-index.jsonl`，它是自动生成文件，下一次重建会被覆盖。

### 4.3 新增或修改 md 后如何入库

新增或修改资料后执行：

```bash
bash scripts/reload-wind-knowledge.sh
```

该脚本会重建：

- `风机故障码/fault-index.jsonl`
- `风机故障码/fault-index-summary.json`
- `wind-llmwiki/fault-index.jsonl`
- `wind-llmwiki/fault-index-summary.json`
- `src/data/windFarmModels.json`

如果只想确认索引是否重建成功，可查看摘要：

```bash
cat 风机故障码/fault-index-summary.json
cat wind-llmwiki/fault-index-summary.json
```

如果要检查某条新故障是否已进入索引，可用关键字搜索：

```bash
grep -n "故障代码" 风机故障码/fault-index.jsonl | head
grep -n "SL1500-ABB" 风机故障码/fault-index.jsonl | head
grep -n "叶轮转速突变" 风机故障码/fault-index.jsonl | head
```

如需常驻监听 md 和 xlsx 变化：

```bash
bash scripts/watch-wind-knowledge.sh
```

该监听脚本会每隔几秒检查 `风机故障码` 目录下的 `.md` 和 `.xlsx`，发现变化后自动执行重建。现场长期维护时可以放在后台运行。

## 5. 场站-型号映射表维护

映射表路径：

```text
风机故障码/故障信息整理/场站-型号映射表.xlsx
```

### 5.1 Excel 表格用途

该表用于把“场站、厂家、机型、具体型号、风机编号”关联起来。用户只说场站、风机编号、机型简称时，系统会用这张表补充检索条件，让故障查询更准。

### 5.2 当前支持列

- A 列：场站
- B 列：制造商/品牌
- C 列：机型
- D 列：型号/具体型号
- E 列或最后一列：编号/风机编号/风机号/机位号/机组编号

表头建议使用：

```text
场站 | 制造商 | 机型 | 型号 | 风机编号
```

最后一列后续可以持续加入对应型号的风机编号。支持一个单元格写多个编号，例如：

```text
F001,F002,F003
F001、F002、F003
1#、2#、3#
```

填写规则：

- 场站不能为空。
- 制造商/品牌尽量和 md 资料里的“品牌”一致。
- 机型用于系列匹配，例如 `CWT系列`、`SL1500-ABB系列`。
- 型号用于更精确匹配，例如 `CWT4200-D175`、`CWT4800-D185`。
- 风机编号可以逐步补充；没有编号时可以先留空，不影响基础检索。
- 不要合并单元格，合并单元格容易导致脚本读取不准。
- 不要把备注写进风机编号列；备注建议另起一列，但不要占用最后一列编号字段。

### 5.3 更新 Excel 后如何生效

更新表格后执行：

```bash
bash scripts/reload-wind-mapping.sh
```

如需自动监听表格变化：

```bash
bash scripts/watch-wind-mapping.sh
```

系统会把编号写入 `turbineIds`，查询结果里显示为“风机编号”。

如果同时新增了 md 和修改了 Excel，建议直接执行：

```bash
bash scripts/reload-wind-knowledge.sh
```

该命令会同时处理 md 资料和 Excel 映射表。

### 5.4 验证 Excel 是否加载成功

检查场站型号数据：

```bash
grep -n "场站名称" src/data/windFarmModels.json | head
grep -n "风机编号" 风机故障码/fault-index.jsonl | head
```

实际使用时也可以在网页中输入：

```text
某场站 某风机编号 故障码60001
某场站 某机型 齿轮箱油压低
```

如果网页返回结果中能看到对应“场站、品牌、机型、具体型号、风机编号”，说明 Excel 已加载。

## 8. 系统资源监控

网页右侧“服务器资源监控”调用：

```text
/api/system-monitor
/api/gpu
/api/cpu
/api/memory
```

CPU 使用率来自 `psutil`。

AMD GPU 显存/温度/功耗依赖 `rocm-smi`。Ubuntu 上常见路径：

```text
/opt/rocm/bin/rocm-smi
```

如果局域网访问页面时显示“无法连接服务器监控接口”，优先检查：

- 页面访问地址是否是服务器 IP，而不是本机回环地址。
- Web 服务是否绑定 `APP_HOST=0.0.0.0`。
- 防火墙是否放行端口 `5002`。
- 浏览器控制台是否有跨域或网络错误。
- 服务器上 `rocm-smi` 是否可执行。

## 9. 常见故障处理

### 9.1 用户登录失败

先用 `admin` 登录网页，进入右上角“用户管理”检查：

- 用户是否存在
- 用户是否被停用
- 密码是否需要重置
- 是否误设为非管理员导致看不到管理入口

只有批量初始化用户或数据库异常时，才由维护人员在工程目录执行导入脚本。

### 9.2 新资料查不到

执行：

```bash
bash scripts/reload-wind-knowledge.sh
```

然后检查索引条数：

```bash
cat 风机故障码/fault-index-summary.json
```

### 9.3 故障码匹配不准

优先检查：

- md 中是否有 `故障代码：`
- 品牌、机型字段是否规范
- 场站-型号映射表是否包含对应厂家和机型
- 用户是否只输入了短码，是否需要补充厂家/机型

### 9.4 大模型不可用

检查 vLLM：

```bash
curl http://10.46.161.210:9527/v1/models
```

检查服务变量：

```bash
echo $VLLM_API_URL
echo $VLLM_MODEL_NAME
```

### 9.5 端口被占用

换端口启动：

```bash
APP_PORT=5017 ./run_web_portable.sh
```

## 10. 维护原则

- 不要直接手工编辑 `fault-index.jsonl`，应修改源 md 或 xlsx 后重建。
- 不要把 API key、`.env`、Flask 密钥、临时凭据文件打进对外包。
- 发布前必须确认用户库、logo、索引、前端构建都已更新。
- 现场问题优先保留原始报码、告警全称、风场、厂家、机型和趋势量截图。
